## 2. 완료된 속도 개선과 다음에 할 일

### 완료: 대체 플레이어 이동 속도 개선
MSE 방식(`fetch → MediaSource → SourceBuffer`)과 10MB 순차 Range 입력 프록시가 적용되었다(`renderer/local-player.js:259`, `lib/preview-stream.js:178`). 앞쪽 버퍼 180초·뒤쪽 60초, 버퍼 안 즉시 이동, 범위 밖 120ms 디바운스 재오픈, 대기 목표를 먼저 반환하는 `getTime()` 으로 연타 누적을 처리한다(`renderer/local-player.js:1`, `renderer/local-player.js:106`, `renderer/local-player.js:351`).

사용자 제공 기존 실측(40tXXfoxqhI, 이번 문서 갱신에서는 재측정하지 않음):

| 항목 | 개선 전 | MSE 적용 후 |
|---|---|---|
| 처음 로드 | 약 9.1초 | 약 4.1초 |
| 버퍼 안 ±10초 이동 | 비교값 없음 | 약 0.04초 |
| 앞쪽 버퍼 | 직접 재생 시 약 2.3초 | 재생 4초 후 약 183초 |
| 범위 밖 이동 | 약 4~5초 | 약 0.8~2.4초 |

실패한 접근: 목표보다 30초 앞에서 스트림을 여는 방식은 브라우저가 아직 받지 않은 구간으로 건너뛰지 못해 폐기했다(이력을 새로 시작하기 전의 실험 커밋이라 해시는 남지 않았다). `<video src>` 직접 재생은 정지 상태에서도 앞쪽 약 2.3초만 받아 버퍼 확대에 한계가 있었다. 서버 출력은 초당 약 10MB 로 충분히 빨랐으므로 입력 속도 개선만으로 해결되지 않았다. 원본 서버 단일 연결의 실시간 약 2배속 제한은 10MB 순차 Range 청크(수십 MB/s)로 개선하고, 브라우저 수신은 MSE 로 제어한다. 이 수치와 실패 원인은 사용자 제공 실험 기록이며 코드 보장값이 아니다.

### 다음에 할 일: 자동 업데이트 첫 실전 검증
- 🔴 푸시·릴리즈는 사용자가 그 턴에 "푸시/배포/올려"를 명시했을 때만. 절차는 `dev-guide.md` §3.
- **앱 자동 업데이트의 "새 버전 감지 → 다운로드 → 재시작·설치" 전체 흐름은 아직 한 번도 실제로 실행해 보지 못했다.** 지금까지 확인한 것은 "현재=최신 → `not-available`" 까지다. 0.5.0 이 릴리즈되었으므로 **0.4.x 설치본(설치형)** 에서 알림 배너가 뜨는지(옛 저장소 주소가 새 주소로 넘어가는 경로 포함), 다운로드·설치·재시작이 되고 이름이 `Stream Cut` 으로 바뀐 뒤에도 설정·대기열이 그대로인지를 사용자 PC 에서 확인해야 한다(결과 대기 중).
- yt-dlp 자동 업데이트의 실제 다운로드·검증·교체는 실제 GitHub 로 확인했다(17MiB, SHA-256 일치, `--version` 일치). 앱 안에서 UI 로 도는 경로는 최신이라 트리거되지 않았다.

## 3. 미결·선택 사항

- **쿠키/로그인 옵션**: 봇 확인("Sign in to confirm you're not a bot")이 걸릴 때를 위한 설정. 후보: Firefox 쿠키(`--cookies-from-browser firefox`)·`cookies.txt` 파일 지정(권장), 앱 안 구글 로그인 창(구글이 임베디드 로그인 차단 가능, 쿠키 회전으로 비권장). 계정 제재 위험 때문에 **켤 때만 쓰는 선택 옵션**이어야 함. 사용자가 아직 결정하지 않았다.
- 컨트롤 줄 버튼이 늘어 기본 창에서 「다운로드」 버튼이 아래 줄로 내려간다(동작엔 문제 없음).
- yt-dlp 가 "JavaScript runtime 없음" 경고를 낸다(기본으로 deno 만 활성). 현재 환경에선 Node 가 PATH 에 있어 문제없었지만, 런타임이 없는 사용자 환경에서 형식이 빠질 수 있다 — 막히기 시작하면 `--js-runtimes node` 설정부터.
- 코드 서명(SmartScreen 경고), 라이선스. (앱 아이콘은 `build/icon.*` 로 추가됨 — 디자인은 재생 버튼 + 구간 선택 핸들, 마음에 안 들면 `build/icon.svg` 를 고쳐 `build/make-icon.cjs` 로 다시 만든다.)
- 4K 처럼 H.264 가 없는 영상은 MP4 가 실패하고 MKV 만 된다(폴백 없음).
- 에러 문구 개선(봇 확인·403 을 사용자가 이해할 안내로)은 쿠키 옵션과 묶어 검토.
- 속도 추가 튜닝·다른 영상의 버퍼/이동 실측은 선택 사항이다. 현재 MSE 개선을 미완료 작업으로 다시 취급하지 않는다.

### 알려진 검증 한계
- 기존 보고상 병렬 부하 때 `real store/jobs/runner persist add and running before spawn, report progress, then complete` 등 통합 테스트가 간헐적으로 실패한다(해당 테스트: `test/integration.test.js:54`). 이번 사본의 `npm test` 는 모두 통과했으며 부하 조건의 재현·원인 확정은 하지 않았다.
- 하드링크 미지원 드라이브의 복사 폴백은 `EPERM`·`ENOTSUP`·`EXDEV`·`EINVAL` 오류 주입으로만 검증했다(`test/runner.test.js:65`). 실제 미지원 드라이브 검증은 남아 있다.
- 이름 변경 후 큐 저장이 실패하면 원래 디스크 이름 복구를 시도한다. 복구까지 실패하면 `RENAME_ROLLBACK_FAILED` 로 보고하고 저장 처리를 중단하므로 디스크와 큐의 수동 확인이 필요하다(`lib/jobs.js:363`).

## 5. 사용자 선호·진행 규칙 (이 사용자와 작업할 때)

- 사용자 전역 설정(`~/.claude/CLAUDE.md`)의 말투 규칙은 대화에만 적용, **문서·커밋 메시지·코드 주석은 한국어 평문**. 커밋 메시지 끝에 `Co-Authored-By` 줄 금지. 의미 있는 변경 커밋 시 **`docs/changelog.md`** 에 변경 이력 추가 — 사용자가 "루트 README 는 간단한 설명만 남기고 모두 docs 로 이관"하라고 지시해서, 전역 규칙의 "README 변경 이력"은 이 저장소에서는 이 파일로 대체한다(루트 README 에는 이력을 쓰지 않는다).
- 질문에는 코드·파일 수정·Bash 없이 답만 하고 의사를 묻는다. "~해주세요/진행해" 같은 명령형은 바로 작업.
- push/릴리즈/배포는 그 턴에 명시적으로 말했을 때만. 로컬 수정·빌드·테스트·커밋은 자유.
- **사용자는 이 앱을 실제로 쓰고 있다**(큐에 본인 클립 `오소리 추천곡 하기` 가 있음). 검증은 반드시 임시 `--user-data-dir`, 사용자 큐·설정 파일을 건드리지 말 것. `taskkill //IM electron.exe` 금지(사용자의 앱이 닫힘) — 내가 띄운 PID 만.
- 진행 상황을 자주 짧게 알리길 원한다(오래 조용하면 말 걸어옴). 병렬로 가능한 건 병렬로.
- 사용자 요청이 도중에 추가되면(같은 파일을 건드리는 작업이 돌고 있을 때) 끝난 뒤 이어서 처리하고, 미리 지시서를 준비해 둔다.
