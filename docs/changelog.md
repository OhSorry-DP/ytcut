# 변경 이력

이 프로젝트의 상세 변경 이력은 이 파일에 기록한다. 루트 `README.md`에는 기능 변경 요약을 기록한다.

## 0.5.1 — 단축키 추가 (미릴리즈)
- Shift+←/→ 로 1분 단위 이동(Ctrl 이 함께 눌리면 1초 이동이 우선한다).
- `[` 키가 다운로드 버튼과 같은 동작을 한다(영상이 준비된 상태에서만, 키 반복 입력은 무시, 텍스트 입력·설정 창에서는 무시).

## 0.5.0 — 이름 변경(Stream Cut)
- 표시 이름을 `Stream Cut`, 저장소·패키지 이름을 `streamcut`으로 변경했다. 설치 파일은 `StreamCut-${version}-${os}-${arch}.${ext}`, 포터블은 `StreamCut-${version}-portable.${ext}` 형식을 사용한다.
- 앱 식별자(`com.ohsorry.ytcut`)와 userData 폴더(`%APPDATA%\YT Cut`)를 유지해 기존 설정·대기열·관리 도구와 설치형 업그레이드·자동 업데이트의 연속성을 보존한다.
- 앱 업데이트 URL을 `OhSorry-DP/streamcut` 저장소로 변경했다.

## 0.4.3 — 앱 아이콘
- 앱 아이콘 추가(재생 버튼 + 구간 선택 핸들): 실행 파일·설치 파일·창·작업 표시줄에 적용. 아이콘 리소스를 넣도록 빌드 설정을 바꿨다(`signAndEditExecutable: true`, 인증서 없음 `forceCodeSigning: false`). 원본은 `build/icon.svg`

## 0.4.2 — 재생 끊김 수정·미리보기 해상도·항상 대체 플레이어
- 미리보기 해상도 상한 360/480/720p 선택(기본 480p)과 「항상 대체 플레이어 사용」(기본 켜짐)을 추가. 기존 설정의 누락만 보정하며 false를 보존한다. 다운로드 화질·큐 snapshot/execution과 무관하고 다음 로드부터 적용한다.
- 기본 모드에서 임베드 플레이어(iframe) 생성 없이 대체 플레이어를 사용. 끄면 iframe 우선이며 101/150/153에서 local로 전환하고, local 실패는 iframe으로 한 번 폴백. 중복 실패·늦은 콜백·왕복 루프를 억제하며 숫자 편집과 다운로드는 유지한다.
- 메타데이터의 formats를 main 내부에 보존해 상한별 재선택·토큰/pending 캐시를 사용하며 스트림 URL은 renderer에 노출하지 않는다.
- 대체 플레이어로 오래 재생하면 「대체 플레이어를 불러오지 못했습니다」 가 뜨던 문제 수정: 미리보기 프록시의 30초 타임아웃이 소비자가 느려서 기다리는 시간까지 포함하던 것을 네트워크 대기에만 걸도록 고쳤고, 소비자가 느려 응답을 오래 열어 두면 원본 서버가 연결을 끊는(ECONNRESET, 약 2분) 경우에는 받은 위치부터 이어 받는다(최대 3번). 플레이어의 복구도 로드당 1번뿐이던 제한을 「직전 복구로부터 15초 뒤 다시 허용」으로 바꿨다. 4분 이상 연속 재생으로 확인

## 0.4.1 — MSE 대체 플레이어·다운로드 파일명 지정
- 설정을 모달로 이동(왼쪽 범주 목록 + 오른쪽 항목: 일반 / 도구 / 앱 업데이트), 사이드패널 스크롤 제거
- 임베드 오류(150/101/153) 영상은 ffmpeg로 영상+오디오를 합친 대체 플레이어로 자동 전환 — 당시 실제 선택은 480p 상한(이전 화면의 360p 표기는 부정확). 타임라인·방향키·Space·I/O·P 동일 동작
- 대체 플레이어 탐색 중 「탐색 중…」 표시
- 대체 플레이어 속도 개선: 영상 정보 조회 결과의 스트림 주소를 재사용(yt-dlp 재호출 제거)하고 키프레임 간격을 1초로 줄여 처음 로드 약 14초 → 9초, 먼 위치 이동 약 9초 → 4~5초
- 문서를 `docs/` 로 정리(구조·계약, 개발·검증·릴리즈 가이드, 인계 문서, 사용자 가이드), 루트 README 는 설명만 남김
- 대체 플레이어를 MSE(MediaSource) 방식으로 교체: `<video src>` 직접 재생은 정지 상태에서도 앞쪽 약 2.3초만 받아 이동이 느렸다. 이제 스트림을 직접 받아 앞쪽 180초·뒤쪽 60초를 유지해, 버퍼 안 ±1/±10초 이동과 빠른 연타는 재오픈 없이 즉시 처리된다. 실측(3시간 40분 영상): 처음 로드 9.1초 → 4.1초, 버퍼 안 이동 약 4~5초 → 0.04초, 범위 밖 이동 4~5초 → 0.8~2.4초
- 방향키를 빠르게 여러 번 눌러도 이동이 누적된다(대기 중인 이동 목표를 기준으로 계산)
- 미리보기 입력을 10MB 단위 Range 청크로 받는 로컬 프록시 추가: 원본 서버 단일 연결의 약 2배속 제한을 피한다(열기 실패 시에만 직접 연결로 폴백)
- 다운로드 버튼 옆에 파일명 입력 추가: 확장자 없이 입력하고, 비우면 영상 제목을 쓴다(윈도우 금지문자는 `_` 로 치환)
- 저장 방식 변경: 완성 파일을 출력 폴더 바로 아래에 `이름.mp4` 로 저장한다. 같은 이름이 있으면 ` (2)` 번호를 붙이고, 완료 후 `<UUID>` 임시 폴더는 정리한다(이전 대기열 항목은 기존 경로 유지)
- 대기열에 지정한 이름을 표시하고, 연필 아이콘으로 바로 이름을 바꿀 수 있다. 완료 항목은 디스크의 실제 파일도 개명하며(실패하면 앱의 이름도 그대로, 같은 이름이 있으면 거부), 다운로드 중인 항목은 바꿀 수 없다
- 탐색기 등에서 파일을 지우면 대기열에 「삭제된 파일」로 표시한다(앱 시작·창 포커스 복귀·대기열 위에 마우스를 올릴 때 확인)
- 알려진 한계: 병렬로 테스트를 여러 개 돌리면 통합 테스트 1건이 가끔 실패한다(단독 실행은 통과)

## 0.4.0 — 자동 업데이트·로딩 표시
- 앱 자동 업데이트: GitHub 새 릴리즈를 감지하면 알림 배너를 띄우고, 누르면 다운로드한 뒤 「재시작하여 설치」로 설치 (설치형 한정, 포터블은 릴리즈 페이지 열기). 시작 5초 뒤와 6시간마다 확인, 설정에서 수동 확인
- yt-dlp 자동 업데이트: 최신 릴리즈가 설치된 것보다 새로우면 앱 데이터 폴더에 받아 SHA-256·버전 검증 후 교체 (다운로드 작업 중에는 끝난 뒤 적용, 사용자 지정 경로는 건드리지 않음, 설정에서 끌 수 있음)
- 대기열 항목/불러오기 로딩 중 플레이어 오버레이와 행 스피너 표시
- 방향키 이동: 영상이 아직 시작되지 않았으면 자동으로 재생을 시작한 뒤 이동

## 0.3.0 — 단축키·시작/끝 지정·실시간 진행률
- 상단 메뉴바 제거
- Windows 빌드(설치형·포터블) 추가, GitHub Releases 로 배포
- 현재 재생 시각을 시작/끝으로 지정하는 버튼과 단축키 (I = 시작, O = 끝)
- 전역 단축키: ←/→ 10초, Ctrl+←/→ 1초 이동, Space 재생/정지 (텍스트 입력 중에는 무시). 포커스된 버튼은 Space로 눌리지 않아 다운로드 중복 실행을 막음. 임베드가 막힌 영상에서도 동일
- 타임라인 세로 크기 축소(108px → 64px)
- 시작점부터 미리 재생 버튼과 단축키 P (끝점에서 자동 정지, 직접 이동하면 해제), 대기열 행에 진행률과 남은 시간 표시
- 구간 다운로드 진행률이 0%에서 멈추던 문제 수정: ffmpeg 진행 시각(-progress)을 읽어 실시간 퍼센트와 남은 시간(ETA)을 계산
